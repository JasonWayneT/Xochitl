# Jason Taylor — Voice Specification

Authority reference for the rewrite-voice skill.
Apply these rules when producing or editing content in Jason's voice.

---

## Stable Traits

These appear across all registers. Apply in every mode.

1. **Friction-reduction as the organizing instinct.** Every design or process decision
   is filtered through: what creates unnecessary effort for the person doing this?

2. **"For now" / "right now" scope limiter.** Decisions are provisional, not permanent.
   Never over-commits.

3. **Anti-pattern before pattern.** Names what he does NOT want before stating what he does.
   Example: *"I don't want this to look like a dashboard inside a SaaS product; I want it
   to look like a genuine work portfolio, easy on the eyes."*

4. **Outcomes before method.** States the desired end state first, works backward to the
   approach. Example: *"The goal isn't to see the full pipeline. I want to see the jobs
   that match and the progress of us getting through it."*

5. **Analogical reasoning.** Every new idea gets a known reference. The analogy IS the
   proposal, not just an illustration of it.
   Example: *"Maybe we can do like a GitHub where, as I finish stuff locally, I can say
   'Sync to Notion.' How's that sound?"*

6. **Explicit pushback invitation.** *"What are your thoughts," "please push back,"
   "challenge me here."* This is a genuine preference, not a courtesy phrase.

7. **Personal layer bleeds into professional content.** Personal anecdotes arrive
   mid-technical-discussion without framing or apology.

8. **Short declarative conclusion after long exploration.** The weight of the short
   sentence comes from everything that hedged before it.
   Example: after a long qualified paragraph — *"My kids having my last name is a
   non-negotiable."*

9. **"I just want…" scope signal.** Reduces to the bare minimum ask. Signals genuine
   minimalism, not laziness.
   Example: *"I just want it to be pointed out if I'm missing something."*

10. **Reasoning by elimination.** Arrives at positions by ruling out alternatives
    explicitly before landing on one.

11. **"I want to make sure that…" verification gate.** Before committing to a deliverable
    or moving forward, names what needs to be confirmed.
    Example: *"I want to make sure that what we just created is our reference material."*

12. **Plan before implementing.** Separates planning from action. Resists changes until
    the plan is reviewed.
    Example: *"No, okay so before you change any more code, I just want to plan and see
    what our implementation plan is going to be before we change anything."*

## Stable Diction Markers

| Marker | Function |
|---|---|
| "Basically" | Oral summary word — compresses complexity into one sentence |
| "For now" / "right now" | Provisional scoping — limits commitment |
| "I think" / "I feel like" / "kind of" / "maybe" | Thinking-out-loud texture — not genuine doubt |
| "Again" | Re-emphasis — signals: this point matters, pay attention |
| "I don't know if…" | Genuine open question — not rhetorical |
| "I just want…" | Scope floor — the minimum acceptable ask |
| "Let's" | Collaborative action — never commands, always invites |
| "At the end of the day" | Professional register only — signals the core claim is about to land |

---

## Anti-Patterns

These never appear in Jason's voice. Their presence means the rewrite missed.

- "Furthermore," "In conclusion," "It should be noted," "Additionally," "Building on this"
- Passive voice or nominalization ("the implementation was completed" → "we got it done")
- Explaining or bridging a metaphor for the reader — let it land without guidance
- Chest-thumping confidence without specificity
- Cleanly resolved paragraphs with no loose threads
- Vocabulary not present in the original (edit and expand modes) — his words are locked
- Claims or content beyond what was seeded (generate mode)
- A third sentence after a two-sentence joke — it kills it

## Register Map

| Register | When to use | Key traits active |
|---|---|---|
| Technical / product | Engineering, requirements, tools, system design | Friction framing, outcomes-first, plan-before-implementing, verification gate |
| Professional / career | Work history, PM processes, career narrative | Conceptual framing, structured examples, "at the end of the day" |
| Personal / reflective | Family, memory, values, social opinion | Flat declarative conclusions, no framing on asides, dry humor |
| Design / creative | UI feedback, aesthetic direction, worldbuilding | Anti-pattern-first critique, analogy as proposal |
