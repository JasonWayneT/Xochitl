# Xochitl - Personal AI Task Management System

## Project Overview
Xochitl (pronounced "so-CHEEL") is a personal AI assistant system that integrates with Notion to help manage tasks using the PARA (Projects, Areas, Resources, Archive) methodology. It uses a local LLM (Gemma 4 E4B) to decompose projects into actionable 30-60 minute tasks, maintains a work-in-progress limit of 3 tasks, and syncs with Notion at the end of each day.

## Core Principles
1. **WIP limit of 3 tasks** - never overwhelming
2. **Priority-driven** - Notion project priority determines task order
3. **30min-1hr task chunks** - actionable, not abstract
4. **Desktop-first, CLI interface** - no custom web UI
5. **Manual sync** - user controls when changes push to Notion
6. **Local LLM** - Gemma 4 E4B (no API costs, no token limits)

## Data Model

### SQLite Schema

```sql
-- Projects (synced from Notion)
CREATE TABLE projects (
    id TEXT PRIMARY KEY,           -- Notion page ID
    name TEXT NOT NULL,
    priority TEXT NOT NULL,        -- 'high', 'medium', 'low'
    status TEXT DEFAULT 'active',  -- 'active', 'archived'
    description TEXT,
    deadline DATE,
    last_synced TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Tasks (generated by LLM or manually added)
CREATE TABLE tasks (
    id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    description TEXT NOT NULL,
    time_estimate_minutes INTEGER, -- 30 or 60
    status TEXT DEFAULT 'todo',    -- 'todo', 'in_progress', 'done', 'blocked'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    completed_at TIMESTAMP,
    notion_task_id TEXT,           -- Link back to Notion if exists
    blocked_by TEXT,               -- task_id if dependency exists
    days_rolled_over INTEGER DEFAULT 0,
    FOREIGN KEY (project_id) REFERENCES projects(id)
);

-- Queue (WIP tracking, max 3 tasks)
CREATE TABLE queue (
    task_id TEXT PRIMARY KEY,
    position INTEGER NOT NULL,     -- 1, 2, or 3
    added_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (task_id) REFERENCES tasks(id)
);

-- Sync history (track what's been synced to Notion)
CREATE TABLE sync_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    synced_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    tasks_completed INTEGER,
    projects_updated INTEGER,
    notes TEXT
);
```

## 3-Layer Context System

### Layer 1: Global Context (`config/global.md`)
```markdown
# Xochitl - Global Context

## Task Management Philosophy
- Use PARA system (Projects, Areas, Resources, Archive)
- Break projects into 30-60 minute tasks
- Maintain WIP limit of 3 tasks maximum
- Prioritize by Notion project priority (High > Medium > Low)
- Tasks rolling over 3+ days need review

## Task Size Guidelines
- Longer projects: 1 hour chunks (e.g., "1 hour reading Chapter 2 of Systems Analysis")
- Daily goals: Specific count (e.g., "Apply to 10 jobs")
- Reading tasks: Chapter-based or time-based (whichever is clearer)

## Sync Strategy
- Pull from Notion: Morning or on-demand (`xochitl pull`)
- Push to Notion: End of day, manual trigger (`xochitl sync`)
- Always ask before syncing if conflicts detected

## Priority Handling
- High priority projects: Fill queue first
- If task due today/tomorrow and not in queue: Interrupt to notify
- Dependencies: Skip blocked tasks, pull next available

## LLM Behavior
- Always plan before acting
- Break down ambiguous requests into concrete tasks
- Ask for clarification if project scope unclear
```

### Layer 2: Project-Specific Context
Example: `config/projects/job-applications.md`
```markdown
# Job Applications Project

## Task Template
- "Apply to 10 [role] positions"
- Daily recurring task
- Each application should include customized resume/cover letter

## Tracking
- Log companies applied to
- Track application status
- Note follow-up dates

## Priority
- High priority
- Should appear in daily queue
```

### Layer 3: Reference Files
- Cached Notion project data
- Project descriptions from Notion
- Task history

## CLI Commands Specification

### Core Commands

#### `xochitl today`
**Purpose**: Generate daily task queue (max 3 tasks)

**Behavior**:
1. Pull latest projects from Notion (optional: can work with cached data)
2. Get all active tasks from local DB
3. Filter out blocked tasks
4. Sort by priority (project priority first, then creation date)
5. Fill queue with top 3 tasks
6. Display queue to user

**Output**:
```
Pulling latest from Notion...
Found 5 active projects. Generating queue...

Your queue (3/3):
1. [Job Applications] Apply to 10 software eng roles (60 min) [HIGH PRIORITY]
2. [Systems Analysis] Read Chapter 2 and take notes (30 min) [HIGH PRIORITY]
3. [Portfolio Site] Update projects page (30 min) [MEDIUM PRIORITY]
```

#### `xochitl done <task_number>`
**Purpose**: Mark task complete and refresh queue

**Behavior**:

2. Remove from queue

5. Display updated queue

#### `xochitl plan "<project_name>"`
**Purpose**: Decompose a project into tasks using LLM

**Behavior**:
1. Load project context (if exists in `config/projects/`)
2. Load global context
3. Call Gemma 4 E4B with prompt:
   ```
   You are a task planning assistant. Break this project into concrete 30-60 minute tasks.

   Project: {project_name}
   Description: {description}
   Priority: {priority}
   Deadline: {deadline}

   Context:
   {global_context}
   {project_context}

   Rules:
   - Each task should take 30-60 minutes
   - Tasks should be actionable (not "research X", but "read Chapter 3 of X and take notes")
   - For reading projects, specify chapters or page ranges
   - For repetitive projects (e.g., "Apply to jobs"), create daily/recurring tasks
   - If tasks have dependencies, note them
   - Return as JSON: [{"description": "...", "time_minutes": 30, "blocked_by": null}, ...]
   ```
4. Parse LLM response
5. Display proposed tasks
6. Ask user to confirm before adding to DB

**Output**:
```
Breaking down "Build personal website"...

Proposed tasks (30-60 min each):
1. Set up Next.js project with Tailwind (60 min)
2. Design homepage layout in Figma (30 min)
3. Build navigation component (30 min)
4. Create projects showcase section (60 min)
5. Deploy to Vercel (30 min)

Add to task list? (y/n)
```

**Purpose**: Push completed tasks to Notion

**Behavior**:
1. Get all tasks completed since last sync

4. Push completions to Notion:
   - Mark corresponding Notion tasks as complete
   - Update project progress percentage
5. Log sync in `sync_log` table
6. Display summary

## LLM Integration (Gemma 4 E4B)

### How to Interface with Local Model

**Assumption**: Gemma 4 E4B is running via Ollama or similar

```python
# Example using Ollama API
import requests
import json

def call_gemma(prompt: str, context: str = "") -> str:
    """Call local Gemma 4 E4B model"""
    
    full_prompt = f"{context}\n\n{prompt}" if context else prompt
    
    response = requests.post(
        "http://localhost:11434/api/generate",
        json={
            "model": "gemma2:4b",
            "prompt": full_prompt,
            "stream": False
        }
    )
    
    return response.json()["response"]
```

### Task Decomposition Prompt Template


## Notion Integration

### Required Notion Setup

**Database Structure**:
- **Projects Database** with properties:
  - Name (title)
  - Priority (select: High, Medium, Low)
  - Status (select: Active, Archived)
  - Description (text)
  - Deadline (date)
  - Progress (number, auto-calculated from tasks)

- **Tasks Database** (optional, or use checkboxes in project pages):
  - Task Name (title)
  - Project (relation to Projects)
  - Completed (checkbox)
  - Time Estimate (number)

### Notion API Integration

```python
from notion_client import Client

def get_active_projects(notion_token: str) -> list:
    """Fetch all active projects from Notion"""
    
    notion = Client(auth=notion_token)
    
    results = notion.databases.query(
        database_id=PROJECTS_DB_ID,
        filter={
            "property": "Status",
            "select": {
                "equals": "Active"
            }
        }
    )
    
    projects = []
    for page in results["results"]:
        props = page["properties"]
        projects.append({
            "id": page["id"],
            "name": props["Name"]["title"][0]["text"]["content"],
            "priority": props["Priority"]["select"]["name"].lower(),
            "description": props.get("Description", {}).get("rich_text", [{}])[0].get("text", {}).get("content", ""),
            "deadline": props.get("Deadline", {}).get("date", {}).get("start")
        })
    
    return projects
```

## Edge Cases & Error Handling

### Rollover Tasks
If a task has `days_rolled_over >= 3`:
1. Display warning during `xochitl sync`
2. Prompt user: Keep, Delete, or Reschedule
3. If Keep: Reset counter, add note
4. If Delete: Mark as archived
5. If Reschedule: Ask for new deadline

### Dependency Blocking
When filling queue:
1. Check if task has `blocked_by` field
2. Query if blocking task is complete
3. If not complete, skip and try next task
4. Log skipped tasks for user visibility

### Notion Sync Conflicts
If project modified in Notion after last sync:
1. Detect via `last_edited_time` comparison
2. Show diff to user (old vs new description/priority)
3. Ask: Pull latest? Keep local? Merge?

### Network Failures
- Cache last Notion pull
- Allow offline mode (work with cached data)
- Queue sync operations for retry when online
