# Project Constitution

## Project identity

- **Project name**: Xochitl (pronounced "so-CHEEL")
- **Product type**: Terminal-native AI Chief of Staff CLI
- **Target users**: Solo developer (personal productivity and AI-assisted app development)
- **Primary problem**: Fragmented personal task management and the absence of a repeatable, traceable AI-assisted app development pipeline
- **Primary value proposition**: A single CLI that manages a daily priority queue with Notion sync (PARA methodology) and runs a full BMAD → SDD → Code Generation pipeline for building new applications
- **Current stage**: MVP

## Operating mode

- **Spec mode**: standard
- Required requirement categories:
  - Functional: yes
  - Non-functional: yes
  - UX/design: no (terminal only)
  - Architecture: yes
  - Data: yes
  - Security/privacy: yes (sandboxing, path restrictions)
  - Operations: no
- **Default priority scale**: P0 | P1 | P2 | Won't have

## Technical defaults

- **Language**: Python 3.12+
- **CLI framework**: `click`
- **Terminal UI**: `rich`
- **Database**: SQLite (local task storage and session history)
- **Remote sync**: Notion via `notion-client`
- **LLM routing**: Tiered via `src/router.py`
  - Local: `gemma4-e4b` (task management, simple QA, file reads)
  - Cloud: Gemini 1.5 Pro/Flash or Claude (complex code, architecture, BMAD)
- **Vector DB**: ChromaDB (long-term memory)
- **Testing framework**: pytest, `smoke_test.py`, `end_to_end_test.py`
- **Package manager**: pip / `requirements.txt`
- **Frontend**: N/A (terminal UI only)
- **Hosting/deployment**: Local only (no cloud hosting)
- **Authentication**: None (single-user, local)
- **Observability**: SQLite session logs, `.sdd/logs/`

## Product boundaries

### Goals

- `GOAL-001`: Provide a daily task queue capped at 3 items (WIP limit) surfaced by `xochitl today`
- `GOAL-002`: Sync completed tasks to Notion using the PARA methodology via `xochitl sync` / `xochitl pull`
- `GOAL-003`: Support the full BMAD → SDD → Code generation pipeline for new applications under `projects/`
- `GOAL-004`: Maintain requirement-to-code traceability across all generated project artifacts
- `GOAL-005`: Provide conversational intent routing via `xochitl chat` backed by TieredRouter

### Non-goals

- `NG-001`: Multi-user or team support
- `NG-002`: Web, mobile, or GUI interface
- `NG-003`: Cloud hosting or SaaS deployment
- `NG-004`: General-purpose code editor or IDE replacement
- `NG-005`: Replacing Notion as the system of record (Xochitl is a sync layer, not a replacement)

## Global quality bar

- **Performance**: CLI commands (`today`, `done`, `sync`, `pull`) respond in <2s; LLM-backed commands may take longer
- **Reliability**: WIP queue always holds 0–3 rows; no data loss on interrupted Notion sync
- **Security**: File operations restricted to allowed roots in `src/security.py`; no credentials stored in plaintext
- **Maintainability**: No raw SQL outside `src/database.py`; all LLM calls via `src/router.py`; all file ops via `FileTools`
- **Traceability**: All code generated by the SDD pipeline must cite requirement IDs (e.g., `# Implements FR-CORE-001`)
- **Documentation**: Specs are updated before code; requirement IDs are cited in tasks and commit messages

## Agent constraints

- Agents must read `docs/spec/` in the required order (see `AGENTS.md`) before editing code.
- Agents must cite requirement IDs in implementation notes and commit messages.
- Agents must never write raw SQL outside `src/database.py`.
- Agents must never call LLMs outside `src/router.py`.
- Agents must never access filesystem paths outside the allowed roots in `src/security.py`.
- Agents must preserve the WIP limit (0–3 rows in the `queue` table).
- Agents must record open questions instead of guessing when a decision changes product behavior.
